## Competing Expert Lenses
### Expert A — one generic structural inference engine
Use the current platform input anchor, climb ancestors, classify flex/grid/block parents, and apply the same inference algorithm across sites.

Strength: less adapter code and faster expansion. Failure mode: broad input fallbacks, secondary composers, decoy editors, responsive variants, and divergent Send selectors can make a plausible ancestor the wrong structural owner. Near Send, that false positive has asymmetric consequence.

### Expert B — adapter-owned structural capability
Give each supported adapter a separate structural capability contract whose absence means structural mounting is disabled. Shared code may implement verification and repair mechanics, but each adapter owns discovery and approved insertion rules.

Strength: matches Ghost's existing reviewed-actuator philosophy and the mobile-shell brief. Failure mode: more maintenance and slower expansion.

### Resolution
**Prefer shared invariants plus adapter-specific structural discovery.** A generic classifier may be a diagnostic/falsification tool, but it may not become placement authority until a particular adapter's current structural evidence proves it safe.

### Reliability / security lens
The most important new boundary is capability separation:

`reviewed actuation adapter != reviewed structural mount adapter`

A future structural mount should require an explicit, fail-closed capability such as a reviewed `mount`/`structure` contract. Missing capability means the existing rail remains the compatibility path. No broad generic fallback may create a structural mount.

### Mobile / performance lens
Cross-adapter expansion multiplies observer/repair and responsive-layout risk. The same invariant suite should be reused across adapters, but host-specific discovery must prevent unnecessary document-wide observation. Existing Round-6 320-CSS-pixel-equivalent, 200%-text, keyboard/reflow, and 1x/4x/6x Chromium stress constraints remain mandatory where applicable.

### Aggregate user lens
The portable user benefit is a consistent Ghost control surface across sites. The least surprising failure behavior is **safe degradation to the existing rail on an unsupported or stale structural contract**, not a best-effort insertion into an uncertain toolbar. No new community sentiment is claimed in this fallback.

### Adoption / upstream lens
ArcRift's explicit platform resolver plus automated selector smoke testing supports platform-specific maintenance rather than a universal selector. PortableBrain confirms anchor convergence but also demonstrates why permissive input fallbacks are unsuitable as mutation authority.

### Outside-frame candidate — structural contract learned from runtime geometry
Automatically learn a site's action row from repeated geometry/co-occurrence observations and promote it after confidence accumulates.

Rejected for first release-critical implementation: confidence scores do not prove Send identity or host ownership, can drift across A/B variants, and would add hidden state/authority where Ghost currently prefers explicit reviewed paths.

### Test / certification lead
Cross-adapter support needs distinct evidence maturity levels so an anchor smoke test cannot be mistaken for mount safety.

## Novel Finding / Decision
Round 6 should use a **three-stage structural evidence maturity model**:

1. **Anchor smoke** — non-actuating fixture or live-page checks show an adapter can find an editor and relevant semantic controls. This may run broadly and can detect obvious selector drift. It grants **no layout mutation authority**.
2. **Structural capture** — current adapter-specific desktop+narrow evidence proves the active editor, composer root, exact reviewed Send relationship, candidate action/footer/header rows, hidden/secondary composer handling, and layout signatures. This is the minimum evidence needed to define an insertion rule.
3. **Mount certification** — the implemented adapter preserves exact Send node identity; produces one Ghost mount; survives host-control insertion and composer replacement; uses only scoped repair; fails closed to the rail; passes zero-actuation, cleanup, 320-CSS-pixel-equivalent, 200%-text, keyboard/reflow, and constrained-runtime invariants.

A future adapter registry should therefore expose **structural capability separately from actuation capability**. Shared code may own the invariant checker, Shadow-host mechanics, scoped observers, and teardown; adapters own structural discovery and approved placement. A site that lacks structural certification must remain on the rail even when Ghost can already read or send there.
