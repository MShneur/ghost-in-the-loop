# v8.5.3 item 1 — assistant answer selection

Status: implemented on the development branch; not released to `main`.

## Failure addressed

Perplexity can expose assistant content through several overlapping selector families. The former adapter appended matches selector-by-selector and returned the final array entry. That entry was not guaranteed to be the latest answer in document order and could be a hidden virtualized duplicate, an outer wrapper, or trailing follow-up UI. A visible `[[GITL::HALT]]` or `[[GITL::PROCEED]]` could therefore be missed.

## Repair

The adapter now:

- deduplicates candidates;
- rejects disconnected, hidden, Ghost-owned, button, follow-up, and suggestion candidates;
- restores global DOM order across selector families;
- considers only a bounded tail of rendered candidates;
- prefers an exact terminal marker in that bounded tail;
- otherwise returns the latest substantial streaming answer;
- exposes metadata internally without storing answer text.

The stable loop engine and at-most-once send transaction remain unchanged.

## Regression cases

- selector-family order differs from document order;
- visible current HALT followed by unrelated follow-up UI;
- hidden virtualized duplicate carrying a stale marker;
- nested answer node inside a wrapper with trailing citations/UI;
- current response still streaming without a marker.

## Release gate

This item stays in draft PR #11. It must pass the normal Jest and Playwright Chromium/Firefox matrix and later be combined with the remaining v8.5.3 items before any merge to `main`.
