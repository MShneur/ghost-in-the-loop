# Ghost in the Loop 8.8.6 — Host Lifecycle / Editor Hardening Research

Date: 2026-09-10
Baseline: `main` / 8.8.5 at `8a5378e78c90923a0fa616df4d8525f0178157d4`
Status: research only; do not mix into 8.8.5.

## Why this exists

8.8.5 is the certified field candidate and has already been promoted unchanged. This lane records external patterns worth evaluating next without destabilizing the working release.

## External corroboration

### ChatGPT selectors

Current OpenCLI ChatGPT automation uses `button[data-testid="send-button"]` as the primary Send selector and `#composer-submit-button` as a fallback, with multiple contenteditable composer selectors. This independently corroborates the 8.8.5 selector repair.

Reference: https://github.com/jackwener/OpenCLI

### Perplexity editor shape

Current MCP-SuperAssistant Perplexity adapter identifies `#ask-input` as a Lexical/contenteditable editor and supports button submission plus Enter fallback. This independently corroborates the 8.8.5 Perplexity host assumptions.

Reference: https://github.com/srbhptl39/MCP-SuperAssistant

### Managed-editor insertion hazards

Recent OpenCues browser-integration notes document two failure modes directly relevant to Ghost:

- a second data-bearing synthetic `input` event after insertion can duplicate content in managed editors including Lexical;
- post-write DOM checks are not a safe signal for firing a second insertion fallback because editor reconciliation can be asynchronous.

That supports the 8.8.5 design: one text-bearing insertion, then only data-less compatibility signalling, with no second automatic write based on an ambiguous post-write observation.

Reference: https://github.com/opencues/opencues

### Lexical event model

Lexical itself exposes `BEFORE_INPUT_COMMAND`, `INPUT_COMMAND`, and `CONTROLLED_TEXT_INSERTION_COMMAND`, confirming that editor state is driven by managed input semantics rather than treating the contenteditable DOM as a normal textarea.

Reference: https://github.com/facebook/lexical

### Content-script lifecycle patterns

WXT's current content-script architecture provides useful patterns for dynamic hosts:

- automatic mount/unmount when a dynamic anchor appears or is replaced;
- content-script invalidation cleanup;
- explicit SPA location-change handling;
- optional Shadow DOM UI isolation.

Reference: https://wxt.dev/guide/essentials/content-scripts

## 8.8.6 candidates

1. **Host lifecycle controller**
   - Separate host/composer lifecycle from send mechanics.
   - Reacquire composers after React/Lexical node replacement.
   - Reset bounded host state on SPA navigation.
   - Tear down timers/listeners when the script context is invalidated.

2. **Explicit editor capability adapter**
   - Detect Lexical/contenteditable vs textarea-like vs other managed editors.
   - Keep host-specific insertion semantics rather than one universal write path.
   - For Perplexity, preserve the 8.8.5 single-write rule and forbid a second text-bearing synthetic input event.

3. **Selector-health telemetry, not selector authority**
   - Record which reviewed selectors were found/connected/enabled.
   - Never promote a learned/guessed selector into Send authority automatically.
   - Use evidence only to propose reviewed selector updates.

4. **Lifecycle certification tests**
   - Composer removed/recreated between rounds.
   - SPA route change without full reload.
   - Extension/userscript reinjection or context invalidation.
   - No duplicate observers, timers, UI panels, or send actuators after remount.

5. **Physical-device canary harness**
   - Keep this separate from production logic.
   - One-tap mobile test should exercise Alpha/Beta/Gamma/Delta and emit a redacted stage report.
   - Preserve the invariant: once a send may have fired, the harness must not automatically try another send path.

## Do not do

- Do not rewrite 8.8.5 around WXT merely because WXT has useful lifecycle primitives.
- Do not replace reviewed Send selectors with heuristic nearest-button discovery.
- Do not interpret `execCommand()` success or immediate DOM length as proof that a managed editor accepted the write.
- Do not chain alternate send actuators after an ambiguous dispatch.

## Recommended next experiment

Implement only the lifecycle controller + lifecycle tests on an isolated 8.8.6 branch. Keep the 8.8.5 send transaction and Perplexity single-write semantics unchanged. Promote nothing until unit, parity, Chromium/mobile/Firefox, and physical-device canary evidence are green.
